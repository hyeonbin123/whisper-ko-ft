# 측정 규칙과 결과

규칙은 재기 전에 적고 커밋한다. 결과는 같은 절 아래에 덧붙인다. 규칙을 바꾸면 바꾼 시점과 이유를 남긴다.

## 공통 규칙 (2026-09-18, 측정 전)

### 데이터 분리
- **Zeroth validation**: Zeroth-Korean train의 화자 105명 중 10명을 떼어 낸다. 화자 ID 문자열의 SHA-256 값을 16진수로 정렬해 앞에서 10명. 이 화자들의 발화는 학습에 쓰지 않는다
- **val-500**: 학습 중 체크포인트를 고를 때 쓰는 작은 묶음. validation 화자마다 발화 ID 순으로 앞에서 50개씩
- **test**: Zeroth-Korean test(457발화), FLEURS 한국어 test, FLEURS 영어 test. 단계가 끝날 때 기준선과 고른 모델 하나만 한 번 잰다. test 수치를 보고 설정을 바꾸지 않는다
- 선택과 판정에는 validation만 쓴다: Zeroth validation, FLEURS 한국어 validation, FLEURS 영어 validation

### 지표
- 한국어는 CER(글자 오류율), 영어는 WER(단어 오류율). 묶음 전체의 편집 거리 합 ÷ 정답 길이 합 (jiwer)
- 정규화: 소문자로 바꾸고, 글자·숫자·공백·작은따옴표가 아닌 것은 공백으로 바꾼다. 한국어는 작은따옴표와 공백을 모두 없앤 뒤 글자 단위로 잰다(띄어쓰기 차이는 오류로 세지 않음). 영어는 공백 하나로 정리해 단어 단위로 잰다
- 신뢰구간: 발화 단위 부트스트랩 1,000번(seed 0)의 2.5~97.5 백분위. 두 모델을 비교할 때는 같은 발화를 뽑아 차이의 구간을 낸다

### 디코딩
- Hugging Face Transformers `generate`, fp16, greedy(`num_beams=1`), 언어 고정(`ko` 또는 `en`), `task=transcribe`, 타임스탬프 없음, `max_new_tokens=256`, 배치 16
- 음성은 16kHz 모노. 30초를 넘는 발화가 있으면 앞 30초만 들어가므로, 넘는 발화 수를 세어 적는다
- 속도는 같은 설정에서 배치 1과 16으로 재고(음성 길이 합 ÷ 걸린 시간), GPU 메모리는 `torch.cuda.max_memory_allocated`. 다른 프로그램이 GPU를 쓰지 않을 때 잰다

### 숫자 표기
- Zeroth-Korean의 정답은 숫자를 한글로 풀어 쓰고, Whisper는 아라비아 숫자로 쓰는 일이 많다. 이 차이는 인식 오류가 아니라 표기 차이다
- **숫자 발화**: 기본 모델 두 개(small, large-v3-turbo) 중 하나라도 가설에 `[0-9]`가 들어간 발화. 1단계에서 묶음마다 목록을 확정하고, 그 뒤로 바꾸지 않는다
- 모든 Zeroth 수치는 "전체"와 "숫자 발화를 뺀 나머지" 두 가지로 보고한다. 판정은 두 수치 모두에 조건을 건다

## 1단계: 기준선 (규칙 2026-09-18)
- 대상: `openai/whisper-small`, `openai/whisper-large-v3-turbo`를 그대로
- 재는 것: Zeroth validation CER, FLEURS 한국어 validation CER, FLEURS 영어 validation WER, 속도, GPU 메모리, 숫자 발화 수
- 판정은 없다. 뒤 단계의 비교 기준이 된다

## 2단계: whisper-small 전체 파인튜닝 (규칙 2026-09-18)

### 공통 설정
- 학습 데이터: Zeroth-Korean train에서 validation 화자 10명을 뺀 나머지. 정답 텍스트는 고치지 않고 그대로 쓴다
- fp16 혼합 정밀도, AdamW, warmup 500스텝 뒤 선형 감소, 실효 배치 32(장치당 16 × 누적 2), 최대 3,000스텝(약 5에폭), gradient checkpointing
- 500스텝마다 val-500의 CER을 재고, 가장 낮은 체크포인트를 그 후보의 결과로 삼는다

### 후보
| 후보 | 학습률 | SpecAugment |
|---|---|---|
| A | 1e-5 | 없음 |
| B | 3e-5 | 없음 |
| C (조건부) | A와 B 중 고른 값 | 있음 (`mask_time_prob=0.05`) |

- C는 고른 후보에서 과적합이 보일 때만 돌린다: 학습 손실은 계속 줄어드는데 val-500 CER이 가장 낮았던 지점보다 상대 5% 넘게 올라간 경우
- fp16에서 손실이 발산(NaN 또는 손실이 시작값을 넘음)하면 그 후보는 실패로 적고, 학습률을 절반으로 낮춘 후보를 하나 추가한다

### 선택 규칙
- 후보끼리는 Zeroth validation 전체의 CER(전체 기준)이 낮은 쪽을 고른다
- 두 후보 차이의 95% 구간이 0을 포함하면 학습률이 낮은 쪽을 고른다

### 판정 규칙 (고른 후보 하나를 기준선 small과 비교)
1. **같은 도메인 개선**: Zeroth validation CER이 기준선보다 상대 20% 이상 낮고, 숫자 발화를 뺀 나머지에서도 상대 10% 이상 낮다
2. **다른 도메인 유지**: FLEURS 한국어 validation CER이 기준선보다 절대 1.0%p 넘게 나빠지지 않는다

| 1 | 2 | 판정 |
|---|---|---|
| 만족 | 만족 | 범용 개선 |
| 만족 | 불만족 | 도메인 전용 (다른 도메인에서는 기본 모델을 써야 함) |
| 불만족 | - | 효과 없음 |

- 영어 WER은 판정에 넣지 않고 보고한다 (한국어만 학습한 비용)
- 2번 질문(작은 모델이 큰 모델을 따라잡는가)은 고른 small과 기준선 turbo를 같은 표에 놓고 답한다. 따로 판정하지 않는다

### test
- 기준선 small, 기준선 turbo, 고른 후보를 Zeroth test, FLEURS 한국어 test, FLEURS 영어 test에서 한 번 잰다
