# 개발 계획 (2026-09-18, 개발 시작 전)

## 목표
공개 한국어 음성 데이터로 Whisper를 파인튜닝하고, **미리 정한 규칙으로 전후를 측정**한다. "파인튜닝하니 좋아졌다"에서 끝내지 않고, 어디서 얼마나 좋아지고 무엇을 잃는지를 수치로 남긴다.

## 측정으로 답할 질문
1. 읽는 말투 51시간(Zeroth-Korean)으로 파인튜닝하면 같은 도메인의 오류율은 얼마나 줄고, 다른 도메인(FLEURS 한국어)은 어떻게 되는가
2. 작은 모델(whisper-small, 244M)을 파인튜닝하면 큰 모델(whisper-large-v3-turbo, 809M)을 그대로 쓰는 것을 따라잡는가. 속도와 GPU 메모리까지 보면 어느 쪽이 나은가
3. 한국어만 학습하면 영어 인식은 얼마나 나빠지는가. 전체 파인튜닝과 LoRA는 이 점에서 어떻게 다른가
4. 전화 음질(8kHz, μ-law)에서는 기본 모델이 얼마나 나빠지고, 전화 음질로 바꾼 음성을 섞어 학습하면 얼마나 회복되는가

## 데이터

| 쓰임 | 데이터 | 크기 | 라이선스 |
|---|---|---|---|
| 학습, validation | Zeroth-Korean train | 51.6시간, 22,263발화, 화자 105명 | CC BY 4.0 |
| test (같은 도메인) | Zeroth-Korean test | 1.2시간, 457발화, 화자 10명 | CC BY 4.0 |
| 다른 도메인 확인 | FLEURS 한국어 validation·test | 위키 문체 읽기 | CC BY 4.0 |
| 영어 확인 | FLEURS 영어 validation·test | 〃 | CC BY 4.0 |

- Zeroth-Korean에는 validation이 없어서 train에서 **화자 기준**으로 떼어 낸다. 같은 화자가 학습과 validation에 함께 있으면 validation이 실제보다 쉬워진다
- 대화체·전화 음성 데이터(AI Hub 등)는 신청과 승인이 필요해 이번 계획에는 넣지 않았다. 전화 음질은 공개 데이터를 8kHz·μ-law로 바꿔서 흉내 낸다 (4번 질문). 실제 통화 음성과 다르다는 점은 한계로 적는다

## 모델과 학습 방식

| 모델 | 크기 | 방식 | 이유 |
|---|---|---|---|
| openai/whisper-small | 244M | 전체 파인튜닝 | 11GB GPU에서 전체 학습이 가능한 크기 |
| openai/whisper-large-v3-turbo | 809M | LoRA | 전체 학습은 메모리가 모자람. 이미 한국어를 잘해서 좋아질 여지가 작을 수 있음 |

- GPU는 RTX 2080 Ti(11GB) 한 장. bf16을 지원하지 않아 fp16 혼합 정밀도로 학습한다
- Hugging Face Transformers `Seq2SeqTrainer`, LoRA는 PEFT

## 알고 시작하는 위험
- **숫자 표기**: Zeroth-Korean의 정답은 숫자를 한글로 풀어 쓴다("이천이십"). Whisper는 아라비아 숫자("2020")로 쓰는 경우가 많다. 그대로 재면 기본 모델이 실제보다 나빠 보이고, 파인튜닝의 이득 일부가 "표기를 따라 하게 된 것"이 된다. 기준선을 잰 뒤 숫자가 나온 발화를 따로 세고, 그 발화를 뺀 부분집합의 오류율을 함께 보고한다 (규칙은 `experiments.md`)
- **fp16 학습의 불안정**: 손실이 발산하면 학습률을 낮추거나 LoRA로 바꾼다. 바꾼 사실을 기록한다
- **작은 test**: Zeroth test는 457발화, 화자 10명이다. 작은 차이로 결론을 내리지 않는다. 발화 단위 부트스트랩으로 신뢰구간을 함께 낸다
- **이미 본 데이터일 가능성**: Whisper의 학습 데이터는 공개되지 않았다. Zeroth-Korean이나 FLEURS가 들어 있었을 수 있다. 확인할 방법이 없어 한계로 적는다
